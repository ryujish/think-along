# 10. Think Along UX 설계

> Think Along의 Session, Memory, Context Engine, AI Router를 사용자가 하나의 자연스러운 AI 경험으로 느끼도록 만드는 UX 구조를 정의한다.

---

## 1. UX의 목적

Think Along의 내부 구조는 복잡하다.

```text
Session
Memory
Decision
Context Engine
AI Router
OpenAI
Anthropic
Gemini
```

하지만 사용자가 이 복잡성을 이해할 필요는 없다.

사용자가 경험해야 하는 것은 하나다.

```text
             THINK ALONG

                  │
                  ▼

        "전에 하던 생각이 있다."

                  │
                  ▼

          "그대로 이어진다."
```

Think Along UX의 핵심 목표:

> **여러 AI가 움직이는 복잡한 내부 구조를 하나의 지속적인 Think Along 경험으로 만든다.**

---

# 2. UX North Star

Think Along의 UX를 설계할 때 가장 중요한 질문은 다음이다.

> 사용자가 다시 설명해야 하는가?

좋은 Think Along UX:

```text
어제

User
"Frontend는 React로 하자."

Think Along
"좋습니다."


오늘

User
"어제 하던 거 계속."

Think Along
"React 기반 구조를 정했고,
다음 단계는 Context Engine 설계였습니다."
```

나쁜 UX:

```text
"어떤 작업을 말씀하시는 건가요?"

"이전 대화를 다시 알려주세요."

"Claude에서는 이전 GPT 대화를 알 수 없습니다."
```

Think Along의 UX는 **재설명 비용을 제거하는 UX**다.

---

# 3. 핵심 UX 원칙

Think Along UX는 다음 원칙을 따른다.

```text
Continuity First

Thoughts, Not Chats

One AI Experience

Invisible Routing

Visible Memory

Recoverable Context

Progressive Complexity
```

---

# 4. Continuity First

일반 AI 서비스의 중심 단위는 Conversation이다.

```text
Chat 1

Chat 2

Chat 3

Chat 4
```

Think Along의 중심 단위는 사용자의 생각과 작업이다.

```text
Project

   │

   ├── Thought

   ├── Decision

   ├── Memory

   └── Progress
```

사용자는 채팅방을 찾는 것이 아니라 **하던 생각으로 돌아간다.**

---

# 5. Thoughts, Not Chats

Think Along에서는 가능하면 다음 용어를 전면에 내세우지 않는다.

```text
Chat History

Conversation ID

Thread ID

Session ID
```

대신 사용자 관점의 개념을 사용한다.

```text
Continue Thinking

Recent Thoughts

Projects

Decisions

Memory
```

내부적으로는 Session이 존재하지만 UX에서는 Session 자체가 제품의 중심 개념이 아니다.

---

# 6. One AI Experience

Think Along 내부에서는:

```text
OpenAI

Anthropic

Gemini

Kimi

Local AI
```

등 여러 AI가 사용될 수 있다.

하지만 기본 Conversation UI에서는:

```text
GPT:

Claude:

Gemini:
```

처럼 표시하지 않는다.

기본 Assistant Identity는 하나다.

```text
Think Along
```

---

# 7. Invisible Routing

내부:

```text
OpenAI
   │
   X
Rate Limit
   │
   ▼
Anthropic
```

사용자 경험:

```text
User
"다음 단계 계속."

Think Along
"좋습니다. 앞에서 정한 구조를 기준으로..."
```

Provider 장애는 시스템의 문제다.

사용자가 처리해야 할 문제가 아니다.

---

# 8. Visible Memory

Routing은 숨기지만 Memory는 완전히 숨기지 않는다.

사용자는 Think Along이 무엇을 기억하고 있는지 확인할 수 있어야 한다.

```text

About You

Projects

Decisions

Current Work
```

사용자는 Memory를:

```text
View

Edit

Delete
```

할 수 있다.

# 16. Card를 클릭하면

사용자가 Card를 선택한다.

Think Along은 단순히 마지막 Message 위치로 이동하는 것이 아니다.

내부적으로:

```text
Project Load

↓

Session Load

↓

Working Memory

↓

Active Decisions

↓

Session Summary

↓

Context Rebuild
```

을 수행한다.

그리고 사용자는 바로 작업을 이어간다.

---

# 17. Resume Prompt

Continue Thinking을 열었을 때 매번 긴 Summary를 보여줄 필요는 없다.

Conversation 마지막 상태를 자연스럽게 보여준다.

예:

```text
Think Along

Context Engine까지 설계했습니다.

다음 단계는 AI Router입니다.
```

그리고 Input이 바로 활성화된다.

라고 물을 필요가 없어야 한다.

# 32. Failover 표시

큰 Alert:

```text
ERROR 429

OPENAI RATE LIMIT

SELECT ANOTHER MODEL
```

금지.

대신 작은 상태:

```text
AI switched automatically
```

또는:

```text
Claude로 전환됨
```

정도로 처리한다.

---

# 33. Failover Toast

예:

```text
────────────────────────────────

Claude로 자동 전환했습니다.

대화 내용은 그대로 유지됩니다.

────────────────────────────────
```

몇 초 후 사라진다.

---

# 34. Failover의 핵심 메시지

사용자에게 중요한 것은 오류 원인이 아니다.

중요한 것은:

```text
Your work is safe.

Your context is preserved.

You can continue.
```

이다.

---

# 35. Failover 중 Streaming

AI 응답 도중 Provider가 실패하면:

```text
Generating...

↓

Connection interrupted

↓

Switching AI...

↓

Regenerating...
```

최종적으로 정상 Response 하나만 남긴다.

---

# 36. Partial Response UX

```text

```

상태로 표시한다.

Fallback 성공 후 정상 Message로 교체한다.

# 118. UX 핵심 원칙 최종 정리

> **사용자는 Chat을 찾는 것이 아니라 생각을 이어간다.**

> **사용자는 Provider를 관리하지 않는다. Think Along이 관리한다.**

> **AI는 바뀌지만 Assistant Identity는 Think Along으로 유지된다.**

> **Routing은 보이지 않게, Memory는 통제 가능하게 만든다.**

> **복잡성은 내부에 두고 Continuity를 사용자에게 보여준다.**

# 119. Think Along UX의 핵심 문장

Think Along의 Architecture를 한 문장으로 표현하면:

> **AI는 실행 엔진이고, 사용자의 연속성은 Think Along이 책임진다.**

Think Along의 UX를 한 문장으로 표현하면:

> **사용자는 새 대화를 시작하는 것이 아니라, 자신의 생각을 계속 이어간다.**

그리고 제품 전체를 관통하는 문장은:

> **AI는 바뀌어도, 생각은 이어집니다.**
