# Think Along — Loop Engineering

## 운영 원칙

모든 작업은 `목표 → 실행 → 관찰 → 조정` 루프로 진행한다. 완료는 작업 수행 여부가 아니라 사전에 정의한 조건과 증거로 판정한다.

각 루프에는 다음을 기록한다.

- 목표와 대표 사용자 시나리오
- 변경 범위와 제외 범위
- 검증 가능한 완료 조건
- 검증 방법과 증거
- 사람의 승인이 필요한 지점
- 반복·중단 조건

같은 실패가 두 번 반복되면 원인을 다시 분석하고, 세 번 반복되거나 제품 결정·보안·데이터 손실 위험과 충돌하면 사용자 판단을 요청한다.

## 완료 보고 형식

```md
## 변경 내용

## 테스트 결과

## 남은 문제

## 다음 루프
```

## 모델 전환 기능 완료 조건

API 호출 성공만으로 완료 처리하지 않는다. 다음 조건을 모두 검증한다.

1. 새 모델이 이전 대화의 핵심 목표를 이해한다.
2. 확정 결정과 검토 중인 의견을 구분한다.
3. 사용자 선호와 프로젝트 상태를 이어받는다.
4. 다른 모델의 독립 기억이나 provider thread ID에 의존하지 않는다.
5. 전환 전후 답변이 확정 결정과 모순되면 이를 탐지한다.
6. 사용자가 선택하지 않은 모델이나 계정으로 자동 전환하지 않는다.

## 제품·UI 루프

```text
제품 정의
→ 사용자 시나리오
→ 정보 구조(IA)
→ 화면 목록과 이동 구조
→ 핵심 화면 와이어프레임
→ 인터랙션·상태 정의
→ 클릭 가능한 UI 프로토타입
→ 사용자 관점 검증
→ 기술·데이터 설계
→ 구현
```

UI 산출물은 `텍스트 구조 → 저해상도 와이어프레임 → 흐름 검토 → 수정 → 고해상도 UI → 프로토타입 검증 → UI 명세` 순서로 발전시킨다.

### UI 루프 1 — 핵심 사용 흐름

대표 시나리오:

1. 사용자가 프로젝트를 만든다.
2. GPT와 대화한다.
3. 중요한 내용을 기억 또는 결정으로 저장한다.
4. 사용자가 Claude나 Gemini로 직접 전환한다.
5. 새 모델이 기존 맥락을 이어받는다.
6. Journey에서 생각의 변화를 확인한다.
7. Insight에서 반복 패턴과 핵심 결정을 확인한다.

완료 조건: 대상 사용자가 별도 설명 없이 시작점, 모델 전환, 기억·결정 저장, 이후 Journey·Insight 확인 흐름을 이해한다.

### UI 루프 2 — 화면 구조

| 영역 | 핵심 기능 |
|---|---|
| Think | AI 대화, 모델 선택, 기억·결정 저장 |
| Journey | 시간순 대화·기억·결정 변화 |
| Insight | 반복 주제, 변화, 충돌, 미결정 사항 |
| Decision | 확정·검토 중·폐기·대체된 결정 |
| Evidence | 결정의 근거가 된 원문 확인 |
| Profile | AI 계정·API Key·기억 관리·내보내기 |

### UI 루프 3 — 핵심 화면 우선순위

첫 묶음은 `프로젝트 홈 → Think 대화 → 모델 전환 및 Context 전달 확인`이다. 이 흐름이 검증된 뒤 Journey → Decision → Insight를 연결한다.

## P0 구현 루프

1. P0-1 Core/UI 경계
2. P0-2 Provider → Account → Model 구조
3. P0-3 Canonical Context 저장
4. P0-4 Context Packet 생성
5. P0-5 수동 모델·계정 전환
6. P0-6 전환 후 세션 연속성
7. P0-7 Decision Memory와 supersede

자동 모델 전환, 자동 계정 전환, 자동 라우팅은 포함하지 않는다. 한도 초과 시 알림과 대체 후보만 제공하고 실행은 사용자가 선택한다.
