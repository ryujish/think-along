# Think Along — Product Principles v0.1

## 제1원칙 — Continuity First

> 무엇보다 먼저, 이어져야 한다.

Think Along에서 가장 중요한 것은 모델 성능도, 에이전트 숫자도 아닙니다. 사용자가 다시 설명하지 않아도 되는 것입니다.

GPT가 답하다 Claude로 바뀌어도:

> “아까 이야기하던 것 계속하자.”

가 그냥 통해야 합니다.

따라서 기능을 결정할 때 첫 질문은 항상 이것입니다.

> 이 기능이 사용자의 생각과 작업을 더 잘 이어주는가?

아니라면 우선순위를 낮춥니다.

## 제2원칙 — Memory Belongs to Think Along

> 기억은 모델의 것이 아니다.

이것은 기술 원칙이면서 제품 원칙입니다.

```text
User
 │
 ▼
Think Along
 ├─ Identity
 ├─ Memory
 ├─ Projects
 ├─ Decisions
 ├─ Conversations
 └─ Current Context
        │
        ▼
   AI Provider
```

OpenAI가 바뀌든 Anthropic이 바뀌든 사용자에게 중요한 기억은 유지되어야 합니다.

그래서 원칙적으로:

> OpenAI conversation ID ≠ Think Along session

입니다. Think Along이 원본 기록을 소유하고 각 모델에는 필요한 Context만 전달합니다.

## 제3원칙 — One AI Experience

> 여러 AI를 보여주는 제품이 아니라, 여러 AI를 하나로 만드는 제품이다.

이 차이가 굉장히 중요합니다.

우리가 이런 화면을 중심으로 만들기 시작하면:

```text
GPT-5.6
Claude
Gemini
Kimi
Qwen
```

결국 또 하나의 멀티 AI 클라이언트가 됩니다.

Think Along의 기본 화면에서는 **Think Along** 하나만 존재합니다.

내부에서는 모델이 계속 바뀔 수 있습니다.

```text
           Think Along
               ↓
      ┌────────┼────────┐
      ↓        ↓        ↓
     GPT     Claude   Gemini
```

하지만 사용자가 AI 관리자 역할을 해서는 안 됩니다.

## 제4원칙 — Invisible Complexity

> 복잡함은 시스템이 감당한다.

내부적으로는 상당히 복잡해질 겁니다.

- Provider health
- Rate limit
- Token budget
- Context retrieval
- Memory ranking
- Context compression
- Model routing
- Fallback
- Retry
- Cost optimization

하지만 사용자는 이것을 공부할 필요가 없습니다. 사용자는 그냥 “계속해.”라고 하면 됩니다.

OpenClaw의 강력한 기능은 참고하되 OpenClaw의 복잡한 사용 경험까지 가져오지는 않습니다.

## 제5원칙 — Automatic by Default, Controllable by Choice

> 기본은 자동, 원하면 직접.

Think Along이 모든 것을 자동으로 한다고 해서 사용자의 선택권을 없애서는 안 됩니다.

기본 경험은 `Think Along Auto`이며 시스템이 작업에 적절한 모델을 선택합니다.

하지만 사용자가 원하면 직접 개입할 수 있습니다.

> “이번 건 Claude로 해.”

> “GPT로 다시 검토해.”

> “Gemini 의견도 보여줘.”

UX 원칙은 다음과 같습니다.

> Simple by default. Powerful when needed.

## 제6원칙 — Never Lose the User's Work

> AI가 실패해도 사용자의 작업은 실패하면 안 된다.

예를 들어 GPT가 답변을 생성하다 `429 Rate Limit`이 발생했다고 합시다. 현재 대부분의 AI 서비스 경험은 “오류가 발생했습니다.”로 끝납니다.

Think Along에서는 다음과 같이 이어져야 합니다.

```text
GPT
 ↓
429
 ↓
Router
 ↓
Claude
 ↓
동일 Context 전달
 ↓
응답 계속
```

Provider 장애는 Think Along 내부 문제이지 사용자의 문제가 아닙니다.

## 제7원칙 — Remember Meaning, Not Everything

> 모든 것을 기억하지 않는다. 중요한 것을 기억한다.

이 원칙이 없으면 Memory가 몇 달 후 쓰레기장이 됩니다.

“오늘 점심 뭐 먹을까?”를 영구 기억할 이유는 없습니다. 반면 “Think Along은 모델이 바뀌어도 하나의 AI처럼 보여야 해.”는 매우 중요합니다.

```text
Conversation
     ↓
Working Memory
     ↓
Episodic Memory
     ↓
Importance / Repetition / Explicit Save
     ↓
Long-term Memory
```

그리고 기억에는 삭제·수정·망각도 필요합니다.

## 제8원칙 — Context Is More Important Than History

> 대화 전체를 보내는 것이 기억이 아니다.

대화 10만 줄을 모델에 전달한다고 좋은 기억 시스템이 되는 것이 아닙니다.

“Think Along 제품 원칙 만들자.”라고 했을 때 필요한 것은 몇 달 전의 모든 대화가 아닙니다.

필요한 것은 다음과 같습니다.

```text
Think Along 제품 비전
+ 최근 OpenClaw 분석
+ 이미 결정된 Architecture 방향
+ 현재 작업 단계
```

따라서 Think Along의 핵심 기술은 단순 저장보다 다음에 있어야 합니다.

> Right Context at the Right Time

## 제9원칙 — Preserve Decisions

> 대화보다 결정을 더 중요하게 기억한다.

프로젝트를 진행하면 수많은 대화가 생깁니다. 그중 가장 중요한 것은 결국 “그래서 무엇을 결정했는가?”입니다.

```text
Discussion

Flutter?
React?
Next.js?

       ↓

DECISION

Frontend = Next.js + React + TypeScript
```

Decision Memory를 별도로 관리합니다.

나중에 AI가 “Flutter로 구현해볼까요?”라고 하면 Context Engine이 다음 충돌을 잡아줘야 합니다.

```text
CONFLICT

기존 결정:
Next.js 사용
```

이 기능은 Think Along의 강한 차별점이 될 수 있습니다.

## 제10원칙 — Model Independence

> 어떤 AI도 Think Along의 필수 의존성이 되어서는 안 된다.

오늘 최고의 모델이 GPT일 수 있습니다. 내년에는 Claude일 수도 있고 전혀 다른 모델일 수도 있습니다.

```text
Think Along Core
      │
      ▼
Provider Interface
      │
 ┌────┼────┬─────┐
GPT Claude Gemini ...
```

모델은 교체 가능한 부품입니다.

Think Along의 자산은 모델 자체가 아니라 **Memory + Context + Continuity + User Relationship**입니다.

## 제11원칙 — Transparent, Not Distracting

> 숨기지는 않되 방해하지 않는다.

사용자에게는 기본적으로 Think Along만 보여줍니다. 하지만 원한다면 다음 정보를 확인할 수 있습니다.

```text
응답 정보
Model       Claude
Reason      GPT rate limit
Context     14 memories
Latency     2.1s
```

모델을 감추는 것이 아니라 모델을 전면에 내세우지 않는 것입니다. 신뢰를 위해 이 차이는 중요합니다.

## 제12원칙 — User Owns the Memory

> 최종적으로 기억의 주인은 사용자다.

Think Along이 사용자를 기억한다고 해서 사용자가 그 기억에 종속되어서는 안 됩니다.

사용자는 최소한 다음 행동을 할 수 있어야 합니다.

- 무엇을 기억하고 있는지 확인한다.
- 기억을 수정한다.
- 기억을 삭제한다.
- 특정 내용을 기억하지 못하게 한다.

장기적으로는 다음과 같은 Memory Center를 제공할 수 있습니다.

```text
My Memory

About Me
Projects
Preferences
Decisions
People
Goals
```

이것은 개인정보 보호뿐 아니라 Think Along의 신뢰성과도 직결됩니다.

## Think Along Core 5

원칙이 너무 많으면 아무도 기억하지 못합니다. 제품팀 내부에서는 다음 CORE 5를 기억합니다.

1. **Continuity First** — 다시 설명하게 만들지 않는다.
2. **Memory Belongs to Think Along** — 모델이 아니라 Think Along이 기억한다.
3. **One AI Experience** — 여러 AI를 하나의 AI 경험으로 만든다.
4. **Right Context at the Right Time** — 모든 것이 아니라 지금 필요한 것을 기억한다.
5. **Model Independence** — AI 모델은 언제든 교체할 수 있다.

나머지 7개는 CORE 5를 구현하기 위한 세부 원칙으로 둡니다.

## Vision에서 기술 구조까지

```text
VISION
AI는 바뀌어도, 생각은 이어집니다.

↓

여러 AI를 하나의 지속적인 AI 경험으로 연결한다.

↓

CORE PRINCIPLES
Continuity → Memory → One AI → Context → Model Independence

↓

기술 구조
Unified Session → Memory → Context Engine → Router → Providers
```
